# 内置局部编辑与回贴

适用于已有图片的改字、纠错、换价、商品变形、包装印刷、局部视觉及用户圈选修改。当前六宫格、已交付高清单图、单独发来的成图均走此流程。仅讨论时先分析。正常沟通中识别位置和意图，由宿主定位区域、写请求并调用工具；用户无需提供坐标、蒙版或命令。主图包内自带脚本，所有程序路径从当前 Skill 所在目录解析。

## 选底图、区域与依据

优先用户指定的版本。用干净原图按实际像素定位；红圈图仅作定位指导。只有带圈截图时优先从任务历史取回匹配干净图。独立任务中找不到对应底图且标记遮住实物、难以可靠复原时，说明具体缺口。可清楚区分的多处需求一次收齐；邻近或共享投影的改动合并为一块，相距较远的区域分开。新窗口如已上传成图和产品图，可直接按独立图片编辑；有指定原任务时沿用其当前版本和真实文案记录。

- 先看完整原图或目标格。由 AI 根据动作或结构决定 **context_box（模型看见的画面）** 和 **polygon（允许贴回的区域）**。圈选只定位问题。托腮、握持、佩戴等需要看全可见主体及其接触物。例如托腮要看下巴、双肩、双臂、持手机的另一只手与桌面支撑。人物几乎占满小样时，直接用完整单格作取景。主体在大画面中较小时，可用清楚的主体裁片，并设 include_scene_context=true 加一张同格全景供定位。全景只是参考，生成仍以第一张附件的取景为准。
- 商品按相同侧别和角度选产品原图。图中可见的主体、部件连接点、开口、遮挡和接触阴影应在取景内。例如修耳机支架要看见耳罩、支架两端及与头梁的连接。参考图不足以辨清的字与按键标识，不自行造字或符号。
- 包装或机身文字以能辨认的实物原文为准；海报文案以用户新文字和本格已确认文案为准。改字通常取整行、标签或价签，保留字体基线、描边及背景。更长的新文案连同需要重新排版的空间一起选。字段 visible_text 写裁片中应出现的准确文字，保留标点和真实换行；删除时写明删除对象和应恢复的底色。
- 小样区域的坐标以整张干净六宫格为原点，panel 标识所在格。脚本把上下文裁框限制在该格。整套换色、换背景等按用户涉及的区域或格分别编辑；整格确需重做时可选满该格，保持角色、准确文案和该格原图依据。高清图和独立成图坐标均以自身左上角为原点。
- context_box 为同坐标系的 [左, 上, 右, 下]，右、下为不含的边界，须完整包含 polygon 且不越出本格或底图。修动作、佩戴、主体变形时应填明确取景。改价或一行字可取完整信息块与相邻排版，或省略 context_box 沿用自动外扩。脚本优先从真实画面补足方形，空间不足才用中性灰留边，回贴时去除填充。
- polygon 围住旧轮廓、预计新轮廓和必要接触阴影，给生成后的轮廓留出合成空间。托腮修复可含手、手腕、袖口、必要前臂与下颌接触处。接缝放在稳定衣料或背景，避开指节、腕关节、五官和接触线。默认 seam=target 按 polygon 柔边合成。仅当整个实际裁框都可改时才设 seam=crop。检查相邻区域的羽化边界，互相影响的区域合为一块。turn 可按需用 90、180、270 读侧排文字。
- 根据[局部编辑提示词](product-repair-prompt.md)写 region.change，明确动作关系、形状、光线、遮挡和接缝地标。附件顺序为干净 crop.png、可选的同格或单图全景、source_ids 对应的实物图。方形裁片已覆盖整格时省略重复全景。标注和蒙版留在本地。

## 领取编辑

所有入口的 request.json 包含真实 user_request 和非空 regions。下面只示意字段。panel、像素多边形、文字和来源均须换成本次数据。

```json
{
  "user_request": {"role":"user","message":"用户原话","message_id":"对应用户消息"},
  "regions": [
    {"panel":1,"context_box":[16,240,260,400],"polygon":[[32,280],[208,280],[208,358],[32,358]],"change":"将这枚价签的金额改成用户指定的数字，保留货币符号、字体和倾角。","visible_text":["¥59.9"],"source_ids":[]}
  ]
}
```

- **六宫格**按[合集修改](composite-revisions.md)运行 composite-revise。替换文案同时提供六格更新后的 panels 和 fact_review。受影响格的 regions 要覆盖全部新文案，产品纠形不改文案时沿用原记录。需要换语言时沿用原有一次文案确认。
- **已交付单图**运行 `node "<skill>/scripts/cli.mjs" hd-claim --run RUN --index N --capability CAP --request REQUEST`。默认最近一次成功版本；指定旧版用 basis_attempt，还原到小样裁片可用 revert_to_original。改营销文案同时提供该格完整 copy（index、title、subtitle、extra_copy、copy_zh）及 fact_review。按确认批次换语言时沿用 panels、locale、copy_confirmation。每处列出最终要渲染的新文字。region.source_ids 可取已登记的任一真实同款原图。
- **独立图片**没有原六图任务时，在当前工作区 work 下选新的运行目录，request 加绝对路径 base（干净底图）、output_dir（本次 outputs 内）以及 references，如 {"P1":"清晰实物原图绝对路径"}。纯海报改字可用空映射。运行 `node "<skill>/scripts/cli.mjs" patch-new --run RUN --capability CAP --request REQUEST`。把每处最终文字记入 visible_text，后续修改以用户所选的完整成图为新底图。
- CAP 为按当前真实工具登记的参考图编辑能力，见 host-compatibility.md；原生工具示例为 {"available":true,"tool":"image_gen__imagegen","explicit_image_paths":true}。宿主能力限制按每块裁片的附件数计算。

## 按区域生成，回贴后交付完整图

下列 SELECTOR 在六宫格时写 `--revision R`，高清时写 `--index N --attempt A`，独立图片时省略。R、A 和区域数来自领取回执。CLI 是当前 Skill 的 scripts/cli.mjs。每处各提交一次，结果未知时续接原调用。

**用户聊天只展示最终完整合成图。** 裁片、选区轮廓、蒙版、全景附件、局部回件及未通过检查的候选均留在内部。Codex 用 `functions.exec` 调用生图时，将原返回留在 `store`，只输出可用于保存的路径或状态。局部流程不要调用 `generatedImage`、`image`、`emitImage`、Markdown 图片或会显示中间图的查看器。已在对话中看过的干净底图可用于选区，裁片边界用坐标及 job.json 核对。有确知仅模型可见的图像检查能力才用它检查中间图。宿主若明确会强制公开局部回件，先找同一工具可用的静默方式。确实没有时，以文字说明限制，勿主动提交会公开中间图的调用。进度用简短文字汇报。

1. 运行 `node CLI patch-start --run RUN SELECTOR --region K`。用 job.json 核对裁框、主体上下文及回贴区域，并核对对应产品原图。submit_once 时从返回的 task_path 读全 tool_arguments，原样调用声明的生图工具。其他宿主按 map-call 映射该单区任务。recover_original 查询原调用。若能确证只领取未调用，则在原任务首次提交。saved 直接跳到下一块。
2. 运行 `node CLI patch-save --run RUN SELECTOR --region K --image FILE --host-evidence EVIDENCE` 保存真实回件。data URL 可用 --response JSON 代替 --image。用户明确要求直接贴回已有满意局部时，复用该局部对应裁框、转向和底图。同取景、同画幅的所选文件可直接作为该区回件登记，注明用户所选来源。历史非方形或历史手工裁片可用原 job.json 和脚本 compose 恢复原始取景。
3. 所有区域保存后，用 `patch-compose` 同样的参数先合成到工作目录。有私有图像检查能力时，在完整图上核对用户点名的问题和接缝。手部看双手的动作分工、手腕与前臂连接、接触和支撑。商品核对同侧原图的轮廓、开口和连接点。改字核对新文案和原排版。需要区分模型回件是否已画错、贴回是否切坏轮廓。确认明显不符时保留真实回件并以 hd-fail 或 composite-fail 记录实际原因（独立任务直接说明），不当成修复成功。没有私有查看能力时，只确认文件、几何和合成状态，交由用户查看完整成品，不声称已目检。运行 `patch-finish` 登记同一合成图。恢复时只用已有回件，不重新提交生成。
4. 六宫格生成独立 revision，之后 hd-preview 展示新版，后续高清继承新小样和文案。高清单图再运行 `node CLI hd-finish --run RUN --only N`，展示返回的带修订号文件，例如 01-r2.png，并给出成品目录。独立图片直接交付 patch-finish 返回的唯一成图路径。用户点名旧文件时以所指版本为准。

编辑由用户明确要求后启动，首次方案、小样生成及首次高清仍沿用各自阶段规则。
