# 宿主自行适配：功能保持一致

用户安装本分享包的请求，包含为当前电脑完成必要兼容调整的意图。优先直接安装；遇到真实环境差异，宿主 Agent 可在自己的解压副本中修复，不必要求小白编写配置。权限与付费行为仍遵守宿主实际规则。

## 先看能力，再看名称

豆包工作、Codex、WorkBuddy 和未列出的 Agent 均按实际能力检查：能否发现并加载 Skill、执行程序、读写图片、绑定多张参考图、调用生图或编辑工具、保存结果和持续记录任务。不要因为叫“豆包”就判定缺少本地执行能力，也不要因叫“本地 Agent”就假设某个工具一定存在。受限入口缺什么就说明什么，不统一要求 MCP。

## 可以自行调整

- 由宿主确认的技能目录、ZIP 层级、安装方式、显示元数据与重载方法。平台有原生导入入口时优先使用。
- Node/Python 的可执行文件、版本、依赖安装方式、UTF-8、系统路径、临时目录、可写工作区。优先利用现有环境，必要时使用独立运行环境。
- 生图接口的字段、嵌套结构、附件路径/ID/URL/实际上传方式、支持的模型与参数、并发限制、同一异步任务查询、实际结果保存与展示。
- 本地图片处理实现可替换为宿主可用的等价工具，但保持读取原件、哈希追溯、等比准备、准确六格裁切和不放大/不拉伸规则；用合成图片验证。适配代码放 adapters/，通过受允许的包装文件调用。

允许改动的现有文件：scripts/install.mjs、scripts/python-runtime.mjs、scripts/image_io.py、scripts/host-adapter.mjs、scripts/map-call.mjs、agents/ 下元数据。新增宿主代码放 adapters/。在其他文件里发现需要改动的接口时，优先用上述包装层解决；不能为了安装通过而改核心约束。

## 必须保留的功能

1. 默认亚马逊美国站、英文文案、1张白底首图＋5张副图；按用户要求换语言并重新列全确认。产品事实依资料，不编造参数、功能或包含物，不进行竞品搜索。
2. 先看产品图并按需补资料；无风格图给A/B/C文字方向，有参考图按原规则分析。风格图不混入生图产品附件，不额外生成风格样图。
3. 六图完整方案与全部上图文案先展示；真实用户单独回复“确认生成”后才生成小样。不得用安装请求、补依赖、换工具或适配测试充当出图授权。
4. 先一张2×3六宫格；用户看过当前小样同意后，再生成六张独立图。新版小样使旧确认失效。高清每张带对应裁切小样、必要角度原图和准确确认文案。
5. 每个授权任务仅提交一次；未知结果等原调用，保存失败只恢复保存。没有自动重画、重试或失败后换服务。用户明确指定修改时，仅处理授权范围。
6. 保留状态、证据、附件隔离和防重复提交。不可通过删除锁、伪造回复或换 run 绕过。只做文件/尺寸基础检查；生成后不新增 AI 视觉验收关卡，由用户验收。
7. 默认一张小样加六张独立图，保持已确认设计；不把六张裁切图当正式高清成品，不机械放大，不承诺精确保真。简短中文交互和下载交付不变。

“功能一致”指上述流程与约束一致。不同生图模型可能产生不同画面，不承诺像素或效果完全相同。无法保留某项必需能力时，说明具体缺口，不能默默改成只有提示词、减少图片数量或跳过确认后声称完整安装成功。

## 修复与验证步骤

1. 保留原压缩包与 release-manifest.json，复制到可写工作目录再适配。不要改安装来源或其他 Skill；不要把凭证写进分享包。
2. 记录当前宿主工具 schema 与环境证据，明确失败原因。调整上面允许的接口文件或新增 adapters/ 包装，不修改核心流程、文案模板和测试来迎合失败。
3. 登记前先运行 `node --test tests/workflow.test.mjs`、`node --test --test-name-pattern="maps|unsupported|native|model|queue" tests/compatibility.test.mjs` 与 `node scripts/verify.mjs`，验证核心流程和接口。完整安装测试会拒绝未登记的改动，因此在第6步登记后再运行完整 `npm test`（或 `node --test tests/*.test.mjs`）。测试可在隔离临时副本执行，不需要真实生图；不能为通过测试而删除完整性检查。
4. 用合成素材和模拟调用验证当前接口：准确提示词、附件顺序/内容绑定、禁止混入风格图、实际支持参数、并发、返回结果与失败恢复。模拟测试通过不能说成真实账号出图成功。
5. 写真实验证报告：host、environment、reason，以及 checks 下 workflow_tests / compatibility_tests / syntax_and_links / attachment_mapping；每项为 passed 与实际命令/结果引用 evidence。不得虚构通过。real_image_generation_tested 只在确有授权且真实出图时写 true。
6. 执行 `node scripts/adapt.mjs --record <报告路径>` 登记允许的改动并更新当前文件清单；核心文件变化会被拒绝。release-manifest.json 始终保留发布原版哈希，bundle-manifest.json 记录本机版本；local-adaptation.json 保存改动范围与验证依据。不要手改发布清单绕过核心校验。
7. 登记后运行完整测试；若失败，继续修复接口并重新验证登记，不能带着失败报告完整可用。随后完成安装/平台原生导入，确认宿主确实能发现技能。本地接口适配报告和凭证留在用户电脑，不自动回传。对小白只说“已按你的电脑适配好”，再给简短使用方法；缺能力则用一句话说明实际缺口。

无本地脚本但有等价文件处理/工具执行能力时，可用宿主包装层桥接真实执行环境；仍需运行同等流程验证。若运行条件完全不具备，宿主可指出所需工具或环境，不能在无验证下改写核心程序并宣称功能一致。
