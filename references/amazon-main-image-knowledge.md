# 亚马逊主图本地知识库

用于产品分析之后、六图方案之前。维护通用商业视觉逻辑，不是实时爆款数据库，不提供虚构销量证据；不搜索Amazon商品页、竞品链接或评论。

## 信息顺序

1. 首图解决“卖什么”：白底、商品完整清晰，仅展示确认包含物，避免道具造成套餐误解。
2. 最重要副图解决“为什么适合我”：用一个有依据的主要利益和直观场景表达，不堆五个功能。
3. 其余副图分别解释操作、可见结构、合理场景、尺寸适配或包含物。按品类选题，见 [六图选题](six-image-planning.md)，不机械套六种模板。
4. 每张独立可读；标题讲利益，画面提供证据。每张只承担主要购买问题，重复信息合并。

## 画面与文案

- 功能驱动商品突出使用任务、握持操作和结构证据；适配驱动商品优先解释有证据的接口、尺寸与使用条件；外观驱动商品突出整体效果、纹理及搭配。
- 使用场景交代环境、动作和结果，产品足够醒目；人物和道具只承担用途、尺度或操作说明，不能喧宾夺主。
- 五张副图尽量覆盖场景、整体、细节等至少三种表现方式，适用时安排两个实质不同的使用环境。不为多样性编造用途。
- 默认英文标题通常3–7词，副标题提供必要补充；英文用自然美国英语，其他语言按当地表达、长度与阅读方向安排，不套英文词数；语义完整断行、明确层级和留白。所有可见营销文字先确认。
- 整套统一摄影、字体与色彩关系，允许布局、距离和主体占比变化。白底首图是风格例外。
- 核对实际接触、受力、支撑、遮挡、比例与光线；不能用“高级、真实、高清”等形容词代替具体设计。

## 本品证据边界

常见购买关注点只是选题假设。没有容量、材料、认证、防水、承重、性能或兼容证明时，不把它写进文案或暗示在画面中；没有尺寸就不生成尺寸数字，没有背面证据不编造背面。不保证点击、转化或平台审核。

在blueprint填写`knowledge_basis: {"mode":"local","application":"本品采用哪些逻辑、如何排序、哪些卖点因缺证据不用"}`。不再填写market_research，不要求URL、日期或研究状态。具体取舍与现有planning_rationale衔接，避免重复长报告。
