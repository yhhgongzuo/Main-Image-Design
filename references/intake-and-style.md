# 普通聊天补资料与参考图优先

## 一轮补资料

所有提问直接写在普通聊天中，以简短编号列表列出缺失问题，用户自由打字回复并上传图片。不使用任何问答弹窗、表单或交互提问工具。首轮优先收集参考图；没有风格参考图且没有明确的风格决定权委托时，必须进入独立的第二环节。第二环节的三个方向应针对当前商品策划，不是固定通用菜单。下方主题表仅供内部检查，不作为用户填写表单。

首轮先检查五个产品主题：产品身份、关键规格、主推卖点、目标买家／用途、价格活动。对会影响当前文案或画面的缺失项合并询问一次，连同平台、风格共最多五组；这是问题分组上限，不是可以跳过产品理解的理由。已经明确的不重复问；用户可以答“不知道／没有资料／按图做”，这只决定如何处理产品资料，不能自动确定风格。**非必填指用户可不提供，不代表助手可不询问。** 完全没有答复不能当作没有资料；部分回答后保留已询问状态，不把漏答写成已知。

先用一两句说明已看到的事实，随后按本品填写问题。护肤美妆可采用以下五组；其他品类更换产品内容，保留相关缺口检查：

| 分组 | 首轮应处理的信息 |
|---|---|
| 平台 | 准备发布／上架到哪个平台？已明确则不问 |
| 产品与规格 | 正式名称、主推容量／尺寸／型号、单件还是套装；已清晰辨认的名称先说明，只问不清楚的部分 |
| 主推卖点与用途 | 最想突出哪几个卖点、给谁用／用于什么情境，有没有本品说明或可用于文案的成分／功效／性能资料？用户无需写完整营销文案 |
| 价格与活动 | 真实售价／活动价／赠品或权益，是否希望上图？可以没有，不能自行编写；明确亚马逊副图不做价格时说明不适用，不机械索要成交价 |
| 视觉资料 | 重点推荐一张喜欢的风格图；少于三个可辨认产品角度时，同组引导补主推卖点对应角度或细节 |

容量、尺寸、数量、价格等从图片读不清时不得估算；包装上出现的功效文字记录为包装信息，不能自动视为用户确认的主推卖点或独立验证结论。产品图足够展示外观，不代表关键资料齐全。五组可合并、删去已知或不适用项，不为凑数重复问。平台和风格不能挤掉相关产品问题，缺少角度时合并到视觉组。

第一轮先查看全部上传图片，区分本品图与风格参考图，记录本品图张数和可辨认的不同角度。触发条件以**少于3个不同产品角度**为准，不只看附件数量。同一角度的重复照片、换背景或单纯裁切不增加角度数；一张合集里的多个清楚视图可分别计数。细节图按实际视角判断，并记录它能支持的卖点，不能为凑数把同角度局部放大算成新角度。风格图、其他商品图不计入。无法辨认的视角记为未知，不猜测精确角度数。

已收到本品图、但可辨认角度少于3个时，**即使其他产品资料齐全，也在第一轮一起询问有没有更多产品角度图**。按本品实际结构给出2–3个最值得补充的角度或细节，优先覆盖用户想突出的卖点，避免机械索要所有方向。缺产品图时先请上传本品图并顺带建议提供不同角度。已有3个及以上不同角度时，不因数量重复追问。用户已经明确没有更多图或只按现有图做时，简短说明现有角度限制并继续。

补角度与平台、风格参考、必要产品参数合并为同一轮，合计最多5组。补角度放入视觉资料组，或与“最想突出什么卖点”合并，不因此省掉相关规格和卖点询问。推荐文案如下，开头根据实际图片改写，只有确实辨认清楚时才说具体数量：

> **目前产品图里的不同角度还不到3个，有没有更多角度的照片可以一起上传？**
>
> 产品角度会影响整套图片的丰富程度和卖点展示。角度太少，六张图容易反复使用同一个视角，看起来比较单一。**建议尽量补充不同角度，尤其是能看清你想突出卖点的照片。**
>
> 比如想突出内部空间，就补内部或打开后的照片；想突出接口、按键、材质或做工，就补能看清对应位置的角度图或细节图。具体补哪些，我会根据你的产品给你建议。
>
> **直接把照片发来，再告诉我“重点展示这里”就行。** 确实没有更多照片，也可以回复“没有更多角度，按现有图片做”。

展示时将上面的通用例子替换为适合当前产品、且已有图或用户资料支持的部位，不暗示未经证实的结构或功能。用户说有图待上传时等待图片；收到补图后重新查看并更新角度与卖点证据；明确没有则按现有图继续；只回答本轮其他问题时记录未补充，按已有证据策划，不反复逼问。完全没有回复仍等待，不把沉默当作没有更多图。未展示的结构不得为丰富角度而编造。

先看全部产品图和已有文字。若用户尚未明确发布／上架平台，必须在本轮一起问“这些图片准备发布／上架到哪个平台？”；已明确平台不重复问。第一轮同时处理风格参考：未上传、未明确回答时询问，有图直接分析，说有待传则等上传。平台与风格和上面的产品主题合并为最多五组，不只问平台与风格就结束。平台未回复先等，不按聊天语言、图片文案或目录名称猜测；用户只说没有产品参数不代表回答了平台。明确选择国内通用才采用国内通用方案，平台确定后再init。问题随品类变化，只问会影响文案或画面的相关信息，不要求用户定义“品牌调性”。

示例（按实际已知资料删减，产品功能不视为已确认事实）：

**有喜欢的风格参考图，请一定先上传给我。一张即可，同行商品图也可以。** 告诉我“我想要这种感觉”，我会参考配色、背景、光影和排版，结合你的产品重新设计。

下面几项直接在聊天里回答就行，知道多少说多少，不用复制表格：

1. 图片准备发布／上架到哪个平台？
2. 产品的正式名称、规格是什么？卖单件还是套装？
3. 最想突出哪些卖点？主要给谁用、用于什么场景？有产品说明也可以一起发。
4. 有没有希望展示的真实价格或活动信息？没有也可以。
5. 请把喜欢的风格参考图发来；不足三个产品角度时，同组说明实际建议补充的角度或细节。确实没有参考图，可以用自己的话描述想要的感觉，或告诉我“没有参考图，你来设计”。

上面仅作措辞参考，实际首轮按五个产品主题检查缺口；参考图引导与第5组属于同一主题。已明确的项目不再问，角度充足仅省去补角度追问，不代表主推卖点与规格已知。包含物不明确且影响展示时合并到产品与规格组询问。

护肤美妆问正式名称、容量／色号、主推卖点、适用人群／用途及可用本品说明；工具/数码问型号、功能规格、包含物；家居问尺寸、用途、安装；服装箱包问尺寸、材质、结构；厨房问容量/尺寸、适用条件、清洁；装饰品问尺寸、材质、摆放/安装。根据品类合并，不把全部细项拆成问卷，不对已清楚资料重复提问。风格项同时突出上传动作、一张即可和同行图可用：

> **有喜欢的风格参考图，请一定先上传给我。建议尽量找一张喜欢的商品图作为参考。** 同行的主图、你收藏的电商图都可以，一张就能开始；有多张风格接近的，也可以一起发。
>
> 不用懂设计，也不用写提示词，告诉我一句 **“我想要这种感觉”** 就行。有图作参考，我会更容易理解你想要的配色、背景和排版，做出来也更容易贴近你的预期。
>
> **同行的图也可以作为风格参考**，我会借鉴它的视觉感觉，结合你的产品重新设计，不会照搬整张图、同行品牌或商品内容。参考图不一定要和你的产品属于同一类。
>
> 确实没有参考图，可以直接打字描述想要的感觉，或告诉我 **“没有参考图，你来设计”**。我会结合产品拟定一个方向，放进完整方案里给你看。

只对尚未明确的风格项展示这段引导，已上传或已明确回答不重复长问。不要把普通产品照片误作风格图。国内任务首轮检查主推规格、目标买家、真实价格与活动是否已明确，对相关缺失项合并询问；用户无资料则按已知卖点承接，不编价格，也不因此退回极简。完整营销文案由AI创作，询问资料不等于要求用户自己写文案。

接受自由回答，用户无需复制问题或表格。风格项独立处理：说有但未上传→等图片；上传且用途明确→分析全部参考，不推荐三个选项；只答其他资料、没答风格项→记录not_answered，进入第二环节，仍提示可上传参考图；明确没有→不反复要求找图，进入第二环节；已有文字偏好但无图→整理一个方向，进入第二环节请用户确认；明确委托AI决定风格→记录真实授权原话后跳过第二环节。完全没有回复→继续等待。“按图片做／按现有资料做／没有参考图／其他你看着办”均不能自动视为风格委托。

产品资料部分回答→使用已答信息，余项未知；明确没有资料→继续分析产品，不将“没有产品参数”扩大解释为没有风格参考或委托AI。身份冲突、包含物会导致首图误导等关键问题可必要澄清；其他资料缺失改选题。用户一开始已明确没有更多资料／按图做，可记录原话而不重问产品参数；尚未明确的平台仍在第一轮询问。产品分析可以继续，完整六图策划必须等风格依据确定。
国内补充：文案和活动资料是可选资料；用户没有文案时，由AI按[国内分支](domestic-design.md)主动创作完整营销文案，不再索要“完整文案”作为继续条件。先写主副标题、营销短句、小字号卖点、说明和底栏，再设计满版布局；无活动资料不编优惠。国内无风格图时拟定的方向仍应体现满版商业排版与可信摄影，依据本品卖点和文字偏好确定，不默认抽象光效海报。

## 第二环节：参考图、文字偏好与风格确认

用户在首次合集前任何时候上传参考图，都切换到参考分析；用运行文档的set-style-references登记，保留产品资料。初稿生成后补图走合集修改中的style_change，不能改写原始风格锁。逐张看全部风格图，提取共同特点，明显冲突时只在聊天中问以哪张为主，不擅自拼混。按用户原话识别整体风格、选择性借鉴或只参考完成度，不自动套用其配色与行业效果。参考意图及本品适配写入style-analysis.reference_intent，见[商业视觉决策](commercial-art-direction.md)。

没有风格参考图时，除非用户明确把风格决定权交给AI，必须先单独确认风格，再展开完整六图方案，不得把两个阶段合并成一次“确认生成”。

- 未给文字偏好：根据本品证据推荐三个有实质差别的文字方向，逐项写名称、配色、背景空间、光影、排版及适配理由；只用普通聊天编号，不用表单或交互工具。方向因商品而异，不能套固定通用菜单。
- 已给文字偏好：引用用户原话并整理一个具体方向，说明如何落到摄影、配色、背景和排版，仍需用户确认；不另塞三个不相关方向。
- 明确说有参考图待上传：等待图片；不能在等待时用三个方向代替参考图。收到明确用于风格的图片后分析并采用，不再三选一；参考之间冲突才澄清主次。
- 无图且用户只说“推荐一个”：按要求只推荐一个，但仍展示给用户确认；用真实的推荐请求作preference记录，不能当作授权AI决定最终风格。
- 明确说“风格你来定／风格也交给AI决定”：可直接拟定一个方向，说明理由后策划六图。仅回复“你来定／你来设计”时，只有紧接明确询问是否把风格决定权交给AI的问题才成立；引用该上下文。产品、文案或一般推荐授权不替代风格决定权授权。

将方向登记在interaction.style.options，保持status=pending，运行style-preview并完整展示返回内容，以普通消息结束本轮等待。用户选定或清楚肯定当前方向后，运行style-confirm；自然语言即可，不要求固定口令。用户提出修改则更新方向、重新展示，等待新版确认；尚未确认时不得标selected或运行六图策划。可以随时改为上传风格参考图，不先做风格候选生图。

保留产品真实颜色和结构，亚马逊首图始终独立白底，国内按已确认角色安排白底商品图。包装配色可作为推荐理由，不能被当作用户选定的整套风格。不得假造参考图、选择或委托；不说没图一定做不好，也不保证有图一定满意。

## 交互记录

V3.9新run的inputs含intake_contract="3.9"。information保留原status/known/questions/response/notes，同时填写coverage五项：product_identity、specifications、selling_points、audience_usage、pricing。每项为{status,evidence}；status为known（真实已有资料）、asked（本轮已问、用户可部分回答）、declined（用户明确无资料或按图做）、not_applicable（说明具体不适用理由）。asked再填question，必须与questions中的原始分组问题一致；同一组可以覆盖多项，不能伪造已询问。declined可用information.response或本项response保存真实用户回复。evidence写实际图中文字、用户原话、已询问主题或不适用理由，不用“资料足够”替代。

另填information.angles={distinct_count,status,evidence}，distinct_count只统计可辨认不同视图；不足三个时status必须为asked或declined，asked附question并与实际分组问题一致，回复来自information.response或本项response。无法辨认的部分不计入已确认数量，在evidence中说明。仅因已上传四张而认为角度够，不能通过语义检查。

information.status=sufficient只用于所有相关主题确实已知或不适用、没有缺失追问的情况。明确没有更多资料时可declined继续，部分回复可answered继续；生成前仍按证据决定选题。首轮实际回复应完整覆盖相关主题，不能等填表时才补造。以下JSON展示基本结构，V3.9按上文补齐coverage与angles，使用init生成的实际空记录。

`init` 自动创建 `interaction.json`，Codex 按真实对话更新。不要向用户展示JSON。所有message与message_id必须来自实际用户消息/轮次标识。脚本只检查记录完整性，无法证明消息真实性。

```json
{
  "run_id": "init返回的run_id",
  "style_reference": {"status":"pending","question":"","response":null},
  "information": {
    "status": "pending",
    "known": [],
    "questions": [],
    "response": null,
    "notes": ""
  },
  "style": {
    "mode": "recommendation",
    "status": "pending",
    "options": [],
    "selected_id": null,
    "response": null,
    "preference": null,
    "presentation": null,
    "confirmation": null,
    "delegated": false,
    "delegation": null
  }
}
```

- style_reference：有风格图为supplied；真实回复已明确有无、已在第二环节确认文字方向或明确委托AI决定风格为answered；只答其他资料、遗漏风格项为not_answered；尚未询问或没等到回复为pending。not_answered/pending不能通过风格锁定、六图方案或生成前检查；可先运行style-preview解决。非supplied须记录实际question和真实response，不把“淘宝，其他按图片做”记录为风格已回答或委托。它独立于information的最多5项产品补资料记录，首轮总问题仍最多5组。
- information：资料足够时 `sufficient`，questions为空，notes说明依据；已追问未回复为 `awaiting_reply`；有部分/完整答复为 `answered`；明确无资料/按图做为 `declined`。后两者保留实际问题（1–5项）、用户response和未知项说明。用户预先说明无资料时，可在questions中记录其已回应的资料主题，不伪称额外问过。
- 产品角度复用information记录，不新增必填字段。known或notes写实际产品图数量、可辨认角度及对应图片、缺少的卖点视图；触发补角度时将实际问题放入questions，response保留用户真实答复。补图后更新记录，并将对应角度和细节用于后续逐图选图；未补图不写成已补齐。
- response统一为 `{role:"user", message:"用户原话", message_id:"真实消息引用"}`。补充原文自动成为CHAT事实可用来源，facts.evidence仍要引用具体原话。
- 有风格图：style固定 `{mode:"reference",status:"ready",options:[],selected_id:null,response:null}`；后上传时response记录实际上传消息。不生成候选。
- 无风格图：options记录三个针对本品的方向，已有文字偏好或用户明确只要一个推荐时可记录一个；每项为 `{id:"A",name:"方向名称",description:"具体配色、背景、光影与排版",fit:"为什么适合本品"}`。单项非委托方向必须在preference保存真实文字偏好或单项推荐请求。不得用产品图、AI自己的推测或一般“按图做”替代preference。
- 普通确认路径：delegated=false；style-preview写status=awaiting_confirmation及presentation（当前选项digest、此前用户消息引用），完整展示后等待新的用户回复；style-confirm依据真实回复写selected_id、response和confirmation。只有确认过当前快照后才status=selected。选项变化使旧digest失效，不能复制旧确认或把第一轮产品答复当第二环节选择。
- 明确风格委托路径：options只记录一个拟定方向，status=selected、delegated=true、selected_id与该方向一致，response保存真实授权，reason说明选择理由，delegation为 `{quote:"用户明确授权AI决定风格的原文",context:null}`。quote须是response.message原文片段，并明确包含风格决定权；若是紧接明确风格委托问题的“你来定／你来设计”，context保存该条真实助手问题 `{role:"assistant",message:"原问题",message_id:"真实引用"}`。仅写delegated=true或reason不够；“推荐一个”与否定风格委托均不能走此路径。脚本检查快照、引用及范围线索，肯定／否定、时序与真实语义仍由宿主核实，不能宣称程序独立证明用户同意。
- 被选方向进入style-analysis：origin=`recommendation`，option_id与name必须匹配选项。不要在分析里声称“参考图显示”。

风格参考已确定、第二环节已确认或有明确风格委托后，才告知将策划完整方案，例如：“按你确认的温暖家居感觉策划，接下来展示六图的全部上图文案和画面思路。”无明确卖点时依据本地主图知识与本品证据策划，不搜索竞品；之后仍必须展示最终六图方案，等待用户单独回复“确认生成”。旧任务没有第二环节证据时，补做确认，不追认AI先前自拟的方向。
