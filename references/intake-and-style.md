# 简短补资料与文字选风格

## 一轮补资料

先看全部产品图和已有文字。用一句话说明已知，不把推断说成事实。缺资料时通常问3–5项，最多5项；有一个关键缺口就问一项。问题随品类变化，只问会影响文案或画面的信息，不索要固定全套表格，不要求小白定义“品牌调性”。

示例（按产品改写，示例功能不是已确认事实）：

我看到这是一款带隔层的桌面收纳盒。下面几项知道多少填多少；没有资料可以回复“没有，按图片做”。

| 想补充的信息 | 你可以这样回答 |
|---|---|
| 尺寸是多少？ | 长×宽×高，带单位；不知道可不填 |
| 主要用来放什么？ | 文具、化妆品等，以实际用途为准 |
| 最想突出的特点？ | 直接用自己的话描述；没有可不填 |
| 买家收到哪些东西？ | 只有本体，或列出包含的配件 |

工具/数码优先问型号、功能规格、包含物；家居问尺寸、用途、安装；服装箱包问尺寸、材质、结构；厨房问容量/尺寸、适用条件、清洁；装饰品问尺寸、材质、摆放/安装。不对已清楚的资料重复提问。

接受自由回答，用户无需复制表格。部分回答→使用已答信息，余项未知；明确没有资料或“你看着做”→继续；没有回复→保持等待。不编造补充答复，不重复追问已明确未知的参数。身份冲突、包含物会导致首图误导等关键问题可必要澄清；其他资料缺失改选题。用户一开始已明确说没有更多资料/按图做，可直接记录该回复而不重问。

## 三个文字方向或上传风格图

用户一开始或看到选项后上传参考图，都切换到参考分析；后上传用运行文档的set-style-references登记，保留产品资料。逐张看全部风格图，提取共同特点，明显冲突时只问以哪张为主，不擅自拼混。有参考图时按用户原话识别整体风格、选择性借鉴或只参考完成度，不自动套用其配色与行业效果，不进入三选一。参考意图及本品适配写入style-analysis.reference_intent，见 [商业视觉决策](commercial-art-direction.md)。无参考图时，完成信息补充后给三个针对当前产品的方向；只输出文字表格，严禁生成样图/风格预览。可结合用户文字偏好提案，但不能假造参考图。

| 选项 | 风格 | 画面感觉 | 更适合突出 |
|---|---|---|---|
| A | 清爽简约 | 浅色背景，柔光，简洁文字 | 产品结构和清楚的信息 |
| B | 温暖家居 | 自然光，合理的居家环境 | 日常使用和生活感 |
| C | 鲜明现代 | 适度色彩对比，利落布局 | 外观和视觉重点 |

上表只是家居示例，不是每次照抄。工具可考虑清晰专业/真实作业/硬朗工业；按商品实际调整。三个方向应在摄影、环境、配色关系、字体气质上有实质区别；保留产品真实颜色和结构，首图始终独立白底。不提供不适用品类的凑数方案。

结尾提示：“可以选 A、B、C，也可以说‘你推荐’。都不喜欢？直接上传喜欢的风格图，尽量提供多张同一风格的图片，方便我参考；只有一张也可以。”等待真实选择或上传。用户明确委托推荐时，选一个并用一句话说明理由。用户提出文字修改则按修改确定方向，不能忽略；必要时更新选项再取得清晰选择。不能把沉默当作选择。若用户在看选项前已明确让AI全权推荐，也展示三种文字方向并说明选用哪种，不再重复等回复。

## 交互记录

`init` 自动创建 `interaction.json`，Codex 按真实对话更新。不要向用户展示JSON。所有message与message_id必须来自实际用户消息/轮次标识。脚本只检查记录完整性，无法证明消息真实性。

```json
{
  "run_id": "init返回的run_id",
  "information": {
    "status": "pending",
    "known": [],
    "questions": [],
    "response": null,
    "notes": ""
  },
  "style": {
    "mode": "recommendation",
    "status": "pending",
    "options": [],
    "selected_id": null,
    "response": null
  }
}
```

- information：资料足够时 `sufficient`，questions为空，notes说明依据；已追问未回复为 `awaiting_reply`；有部分/完整答复为 `answered`；明确无资料/按图做为 `declined`。后两者保留实际问题（1–5项）、用户response和未知项说明。用户预先说明无资料时，可在questions中记录其已回应的资料主题，不伪称额外问过。
- response统一为 `{role:"user", message:"用户原话", message_id:"真实消息引用"}`。补充原文自动成为CHAT事实可用来源，facts.evidence仍要引用具体原话。
- 有风格图：style固定 `{mode:"reference",status:"ready",options:[],selected_id:null,response:null}`；后上传时response记录实际上传消息。不生成候选。
- 无风格图：options为三个 `{id:"A",name:"名称",description:"背景光影排版的简短说明",fit:"适合突出什么"}`；待选为 `awaiting_selection`；已选为 `selected`，记录selected_id和真实response。明确委托推荐增加 `delegated:true,reason:"简短理由"`。
- 被选方向进入style-analysis：origin=`recommendation`，option_id与name必须匹配选项。不要在分析里声称“参考图显示”。

选定后告知将策划完整方案，例如：“已选B温暖家居风，接下来展示六图的全部上图文案和画面思路。”无明确卖点或委托AI发挥时依据本地主图知识与本品证据策划，不搜索竞品；无论资料/风格是否齐全，都必须展示最终方案，等待用户单独回复“确认生成”。
